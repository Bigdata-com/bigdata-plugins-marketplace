## What changes

### 1. The body keeps only lines the agent would not supply itself

None of the skill-creation guidelines sets a word ceiling. The test they do set: a line earns its place when it tells the agent something it does not already know or would not do by default. Applied here, a line stays when it is one of three things: a Bigdata.com data fact (five periods per pull, consensus has no history, the risk-free rate is in the country data), a method choice that differs from what a model does on its own (expectations first, a three-year rolling ROIIC, probabilities from a reference class, average the values), or a mistake a run has made, with the reason (the Nvidia beta). What the agent already knows about a DCF, the gather-then-analyse sequence, the "done when" lines, the fixed table lists and the tool arguments all go. Direction, not steps, because a valuation is high-freedom work: the question decides the order and the depth.

Valuation has the most method choices and the most recorded mistakes, so the other 21 bodies come out shorter. Marko's "Yes" on the 26 October re-cut is read as a yes to the direction; the shape below is the one to confirm.

### 2. The reading budget is cut and then measured

Every run reads the tool guide and the rules file before the body, so those two set the floor:

| File | Today | After | What goes |
|---|---|---|---|
| `library/working-with-bigdata.md` | 3,035 words | about 900 | The tearsheet section table, the saving and monitor paragraphs, the error paragraph and the search tutorial. The tool descriptions carry these, and the 17 tool-description requests already written for the MCP team are their proper home. The two routing tables and the data realities stay, one line each. |
| `library/output-standard.md` | 1,534 words | 486 | Approved on the review page. |
| A skill body | 2,300 to 3,300 words | What the test above leaves; valuation comes to about 900 | The procedure, as above. |

The budget is at most 3,000 words read before the first Bigdata.com call. Body, tool guide and rules file come to about 2,300, which leaves room for one section of one method file. The number is measured, not assumed: for every eval run, the transcript lists the files read before the first Bigdata.com call, and the eval scripts count their words and the number of method files opened over the whole run (an extension of the script that already reads timing from the transcripts). The two figures go on the Eval Reader page beside each run. A skill over the budget in two of its runs fails the round whatever its score, because the budget is the fix for the problem the 26 October runs showed, and a rule nobody measures is not a fix.

### 3. A pass rule, fixed before the rerun

- Two prompts per skill, taken from that week's news: one in a portfolio manager's voice, one in a corporate voice. Where the skill has a short form, one of the two is a one-line question. All 44 prompts go on the Eval Reader page for Marko to read before any run.
- Two arms: with the skill, and without it. The no-skill arm is the same Opus model with the same Bigdata.com tools and the server's own instructions, no plugin.
- A Sonnet agent in the reader's persona reads the two reports without knowing which arm wrote which (the order is random), says which one it would use, and gives the reason. A tie counts against the skill. Beside the judgement, the counts: words read before the first call, method files opened, n/a cells, numbered citations, investor terms in a corporate report, tokens and minutes.
- A skill passes when it wins the two pairs, stays within the reading budget, and costs at most 1.5 times the no-skill tokens. A skill that wins one pair gets one rewrite with a named cause and a rerun of the lost pair only. A skill that loses the two is dropped or merged, not rewritten.
- Every pair is on the Eval Reader page side by side for Marko. His call overrides the judge and is recorded with a comment.

The 26 October checks were the output standard's own rules, so the with-skill arm passed them by construction. A blind reader choice is the only measure that matches the goal.

### 4. Every surviving skill goes through the round

22 skills (26 less scenarios, macro-compare, catalysts and watchlist), two prompts each: 44 pairs, 88 report runs, 44 judge runs. The 26 October round was 20 report runs for 6.6 million Opus tokens, about $55 at list prices, so 88 runs at the same size is about $240, plus about $25 for judging and counting. Shorter bodies should read less, so that is an upper estimate. Wall time is about a day in batches of six. The output is a scoreboard on the Eval Reader page (pairs won, words read, cost per skill) and three lists: passed, one rewrite, dropped. The host packages are built from the passed list only, and the 20 Cowork skills are chosen from it.
